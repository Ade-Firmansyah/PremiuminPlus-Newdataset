# Premiumin Plus v3.2 Production Rebuild

Note: this is a historical rebuild snapshot. For the current project rules, use `docs/11-current-project-prd.md` and `docs/01-prd.md`.

Tanggal rebuild: 2026-05-12

Dokumen ini menjadi ringkasan implementasi v3.2 berdasarkan seluruh docs canonical project.

## Stack Final

- Frontend: React, TypeScript, Tailwind, shadcn-style local UI patterns, Motion.
- Backend: Express.js, MySQL, HMAC JWT, service layer, repository layer.
- Database: MySQL canonical schema dengan runtime schema repair.
- Provider: Premku hanya boleh diakses oleh `backend/src/services/premku.service.js`.

## Contract Utama

- Auth UI memakai JWT Bearer token.
- API key tetap tersedia untuk reseller/API integration, bukan sumber session UI utama.
- Frontend tidak pernah memanggil Premku langsung.
- Harga final dihitung backend.
- Saldo yang bisa dipakai transaksi adalah `saldo - locked_balance`.
- Payment success tidak dianggap sama dengan order/provider success.
- Akun produk hanya boleh ditampilkan setelah provider/order success.

## Backend v3.2

Implemented:

- JWT utility tanpa dependency eksternal di `backend/src/utils/jwt.js`.
- Auth middleware menerima Bearer JWT dan masih menerima `x-api-key` untuk API reseller.
- Cache layer in-memory TTL di `backend/src/services/cache.service.js`.
- Product sync guard:
  - Product response cache 15 detik.
  - Provider product sync guard 60 detik.
- Payment/deposit status guard 5 detik.
- Provider order sync scheduler 60 detik untuk order `pending`/`processing`.
- Maintenance scheduler untuk expired QR dan temporary logs.
- Canonical pricing validator:
  - `member_price`
  - `reseller_price`
  - reseller markup wajib lebih kecil dari member markup.
- Wallet usable balance:
  - `saldo`
  - `locked_balance`
  - `usable_balance`

## Frontend v3.2

Implemented:

- API wrapper mendukung Bearer JWT.
- Session menyimpan `token` dan `api_key` secara terpisah.
- Existing dashboard/admin pages tetap memakai backend API; tidak ada fake data.
- Route protected tetap berbasis session terverifikasi lewat `/api/me`.
- Entry project tetap `frontend/src`.

## API Compatibility

Routes docs yang diselaraskan:

- `GET /api/orders/:invoice`
- `POST /api/payments/:invoice/cancel`
- `POST /api/deposit/:invoice/cancel`

Legacy aliases tetap tersedia untuk transisi:

- `GET /api/order/:invoice`
- `POST /api/payments/cancel`
- `POST /api/deposit/cancel`

## Risiko Tersisa

- UI masih memakai komponen lokal bergaya shadcn, belum meng-install package shadcn CLI.
- Direct QRIS order masih melakukan order provider saat status payment dicek sukses; flow sudah idempotent, tetapi pemisahan worker penuh bisa dibuat lebih kuat di fase berikutnya.
- Cache in-memory cocok untuk single instance. Jika deploy multi-instance, pindahkan adapter cache ke Redis.
- Light mode sudah punya session preference dan root class hook, tetapi sebagian panel lama masih dominan dark-token dan perlu polishing visual menyeluruh jika light theme harus sempurna.
